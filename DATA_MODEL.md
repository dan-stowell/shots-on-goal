# Shots on Goal – V2 Data Model

The orchestrator now stores all runtime state in the V2 schema. The design is
append-only (no updates/deletes), normalized (foreign keys instead of JSON
blobs), and records git state, tool usage, and validations explicitly.

## Design Principles

1. **Append-only history** – every change is an INSERT.
2. **Normalized relations** – tables reference each other via foreign keys.
3. **Explicit git tracking** – branches/worktrees are first-class records.
4. **Reproducible tooling** – tool definitions are session-scoped; attempts log
   which tools were available and actually used.

All tables include an `id` primary key and `timestamp` creation column unless
noted.

## Core Tables

### session
```
session(id, timestamp, initial_goal, model_a, model_b, flags, repo_path, base_branch)
```
Represents a single run (CLI invocation). `flags` is JSON with runtime options
such as `max_tools`, `max_goal_breakdowns`, etc.

### tool
```
tool(id, timestamp, session_id, name, description)
```
Session-scoped tool definitions (fresh per run). Tools are not labeled read-only
in the schema; orchestration decides which tools to attach to each attempt.

### goal
```
goal(id, timestamp, session_id, goal_text, parent_goal_id,
     order_num, source, created_by_attempt_id)
```
Root goals (`source='cli'`) come from the user, sub-goals (`source='breakdown'`)
are generated by a breakdown attempt. `created_by_attempt_id` links a sub-goal
to the attempt that produced it.

### validation_step
```
validation_step(id, timestamp, goal_id, order_num, command, source)
```
Ordered validation commands (expected exit code 0). `source` indicates
origin (`cli`, `breakdown`, etc.).

### branch
```
branch(id, timestamp, session_id, name, parent_branch_id,
       parent_commit_sha, reason, created_by_goal_id)
```
Git branches created during the run. The name is globally unique per session
and includes session/goal identifiers.

### worktree
```
worktree(id, timestamp, branch_id, path, start_sha, reason)
```
Git worktrees used for isolation. Each attempt references exactly one worktree.

### attempt
```
attempt(id, timestamp, goal_id, worktree_id,
        start_commit_sha, prompt, model, attempt_type)
```
Records the start of an LLM attempt. `attempt_type ∈ {implementation, breakdown}`.

### attempt_tool
```
attempt_tool(id, timestamp, attempt_id, tool_id)
```
Junction table describing which tools were made available to the attempt.

### attempt_result
```
attempt_result(id, timestamp, attempt_id,
               end_commit_sha, diff, status, status_detail)
```
Outcome of an attempt (statuses such as `success`, `completed`, `error`,
`timeout`, `tool_limit`, etc.). `diff` captures the repository diff at exit.

### tool_call
```
tool_call(id, timestamp, attempt_id, order_num,
          tool_id, tool_name, input, output)
```
Append-only log of every tool invocation. `tool_name` is denormalized for
easy inspection; `input`/`output` are stored as text (usually JSON strings).

### validation_run
```
validation_run(id, timestamp, validation_step_id,
               attempt_result_id, exit_code, output)
```
Stores the outcome of running a validation step against an attempt result.

### merge
```
merge(id, timestamp, from_branch_id, from_commit_sha,
      to_branch_id, to_commit_sha, result_commit_sha)
```
Records successful merges of attempt branches back to parent branches.

### Indexes

To keep common lookups fast the schema creates several indexes:

- `idx_goal_session` on `goal(session_id)`
- `idx_goal_parent` on `goal(parent_goal_id)`
- `idx_attempt_goal` on `attempt(goal_id)`
- `idx_tool_call_attempt` on `tool_call(attempt_id)`
- `idx_validation_run_step` on `validation_run(validation_step_id)`

## Typical Flow

### Implementation Attempt
1. Create root `goal` from CLI prompt (plus any `validation_step` rows).
2. Create unique `branch` + `worktree` for the attempt.
3. Insert `attempt` row (type `implementation`); attach eligible tools via
   `attempt_tool`.
4. Each tool invocation writes a `tool_call` record.
5. When the LLM exits, insert `attempt_result` (status + diff).
6. Run each `validation_step`; log outputs in `validation_run`.
7. On success, merge branch and insert `merge` record (future worktrees begin
   from that commit).

### Breakdown Attempt
Same structure, except:
- `attempt_type='breakdown'` with a read-only tool set.
- Resulting sub-goals populate the `goal` table (`created_by_attempt_id` set).
- Sub-goals inherit the branch/worktree state for focused follow-up attempts.

## Relationships

- `session 1→* goal`
- `goal 1→* attempt`
- `attempt 1→1 attempt_result`
- `goal 1→* validation_step`
- `attempt 1→* tool_call`
- `attempt 1→* attempt_tool`
- `branch 1→* worktree`
- `attempt → worktree → branch`
- `validation_step 1→* validation_run`
- `goal (parent) 1→* goal (children)`

## Notes

- The legacy v1 schema has been removed; all orchestration uses this V2 design.
- Tool execution and validations happen inside the container specified at runtime.
- The schema captures enough information to audit or replay each attempt end-to-end.
- Branch naming conventions:
  - Persistent goal branch: `s{session_id}-g{goal_id}` (e.g., `s1-g3`)
  - Attempt branch: `s{session_id}-g{goal_id}-a{attempt_id}-{timestamp}` (e.g., `s1-g3-a5-1729123456`)
  - Breakdown attempts use the same naming pattern (distinguished by `attempt_type='breakdown'` in the database)
- Successful attempt results are merged back into the persistent goal branch; subsequent attempts branch from the latest success rather than the original base branch.

## Example Queries

```sql
-- All sub-goals produced by a breakdown attempt
SELECT id, goal_text
FROM goal
WHERE created_by_attempt_id = :breakdown_attempt_id
ORDER BY order_num;
```

```sql
-- Tool calls vs tools offered (unused tools)
SELECT t.name
FROM tool t
JOIN attempt_tool at ON at.tool_id = t.id
WHERE at.attempt_id = :attempt_id
  AND t.id NOT IN (
      SELECT tool_id FROM tool_call WHERE attempt_id = :attempt_id
  );
```

```sql
-- Ancestry from root goal to current goal
WITH RECURSIVE goal_path AS (
  SELECT g.*, 0 AS depth
  FROM goal g
  WHERE g.id = :goal_id
  UNION ALL
  SELECT parent.*, depth + 1
  FROM goal parent
  JOIN goal_path gp ON parent.id = gp.parent_goal_id
)
SELECT * FROM goal_path ORDER BY depth DESC;
```

```sql
-- Branch + worktree information for an attempt
SELECT b.name AS branch, w.path AS worktree_path, w.start_sha
FROM attempt a
JOIN worktree w ON w.id = a.worktree_id
JOIN branch b ON b.id = w.branch_id
WHERE a.id = :attempt_id;
```
